## Behaviour that changed

- **Back button** follows real history (studio → location → map → start); it used to skip the location.
- **Address bar:** an old link such as `/?share=X` ends at `/gedeeld/X`, so a shared link now survives a refresh.
- **Teacher class page** no longer flashes a spinner every 20 seconds behind a presentation.
- **Reopening a teacher screen** shows the previous list at once and refreshes in the background.
- **Network failure on classes/submissions** shows about 3 s later (two automatic retries).
- **Deleting a composition** also removes it from the localStorage backup, so a child's deleted work does not stay readable on a shared device.
- **First load is heavier:** router +30 kB, query +10 kB, Dexie about +30 kB (all gzipped).
- **First visit downloads the active theme in the background** (about 10 MB for `basis`), so the lesson works offline afterwards.

## Deploy — this changed, read before the next upload

1. Upload everything **except `sw.js`** first; upload **`sw.js` last**.
2. **Keep the previous release's files in `assets/`** for one release, so devices still on the old version can load their screens.
3. After the upload, check that `sw.js`, `*.html` and `manifest.json` are served with `no-cache`.
4. If something goes wrong: upload `docs/v2/sw-kill-switch.js` as `sw.js`. It clears all caches and unregisters on every device.
5. Renamed or replaced audio/image files must get a **new file name**; a file replaced under the same name can stay stale for up to 60 days on devices that cached it.

Full steps: `docs/v2/OFFLINE.md` and `docs/DEPLOY-INSTRUCTIES.md`.

## Open points and known limits

| Item | Note |
|---|---|
| Refresh in the studio | Goes to the start screen with "Verder werken" (as before), not straight back into the studio. |
| Both storages full | If IndexedDB and localStorage are both full, the child has already been told the save worked; the error is logged and retried but not shown. |
| `max_classes = NULL` | Treated as a limit of 8, while the docs say NULL means unlimited. Existing behaviour, left unchanged. |
| Failed class creation | The create dialog stays on "bezig…" while the error banner sits behind it. Existing behaviour, left unchanged. |
| Component-local teacher fetches | `ClassMembersPanel`, peer-feedback panels, usage stats still fetch on their own; candidates for a follow-up. |
| Retries | Most data functions translate the Supabase error into a message, so only classes and submissions retry automatically. |
| `viewport-fit=cover` | Not switched on; the safe-area padding from Phase 1 therefore has no visible effect yet. Needs a check on a real iPhone/iPad first. |
| Storyboard and praatplaat images | Cached only after they have been shown once online. |
| Safari | May clear the offline cache after 7 days without a visit. |
| One stalled test run | One full end-to-end run hung for about an hour during the service-worker work; reruns pass. Cause not found. |
